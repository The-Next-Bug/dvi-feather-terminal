Flashing the DVI terminal firmware
==================================

Files: dvi_terminal-<target>.uf2 for each supported board:

  pico2-dvi-sock      Raspberry Pi Pico 2 (RP2350) with the Pico DVI Sock

It uses UART0 on GP0 (TX) and GP1 (RX). RP2040 boards (such as the
Adafruit Feather RP2040 DVI) are no longer supported.

1. Hold the BOOT button, press and release RESET, then release BOOT.
   (Or hold BOOT while plugging in USB.) The board appears as a USB drive
   named RP2350.

2. Copy the .uf2 for your board onto that drive. The board reboots into
   the new firmware when the copy finishes.

   picotool also works: picotool load -x dvi_terminal-<target>.uf2

3. Connect a DVI/HDMI monitor. The display runs at 800x600 60 Hz.
   The logo shows for 10 seconds, with the build id on the bottom line,
   then the terminal starts (at once if data arrives on the RX pin, UART0
   115200 8N1, or a key is pressed).

4. Optional USB keyboard: after flashing, unplug the PC from
   the USB port, connect the keyboard there through an OTG adapter, and
   power the board with 5 V into VBUS (pin 40): in host mode the board does
   not power the keyboard itself. Never feed 5 V in while a PC is plugged
   into the USB port. See the README, "USB keyboard".

5. Optional Z80 CP/M machine: in SET-UP (F12) set Mode to "CP/M machine"
   and save; the board restarts as a CP/M computer. Wire an SPI microSD
   adapter to GP4 (MISO), GP5 (CS), GP6 (SCK), GP7 (MOSI), 3V3 and GND,
   with a FAT32 card; I in the monitor installs the built-in CP/M 2.2 disk.
   See the README, "Z80 CP/M machine".

6. Later updates without a PC connection: copy the UF2 to the root of the
   CP/M machine's SD card as FIRMWARE.UF2 (sdcard-<target>/FIRMWARE.UF2 in
   this ZIP), and press U in the CP/M monitor. It checks the file, asks,
   writes it beside the running firmware, then installs it and restarts;
   do not power off while it says so. If the power fails then, the board
   does not start: flash it again as in steps 1-2 (the boot ROM's BOOTSEL
   mode always works). See the README, "Updating the firmware from the SD
   card".

The BIN files are the same images as raw flash contents, for SWD programmers
(load at 0x10000000). SHA256SUMS covers the UF2 and BIN files.

THIRD-PARTY.md lists the open-source components and data built into the
firmware (pico-sdk, TinyUSB, z80pack, FatFs, Terminus Font, the CP/M disk
images) and their licences; the licence texts are in licenses/.
